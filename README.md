## 回测用法

```bash
python backtest.py output/price_history_515180.csv              # 红利（默认 fee=slip=0.001，当日收盘成交）
python backtest.py output/price_history_515180.csv --oos        # 样本内/外分段（默认 70/30）
python backtest.py output/price_history_515180.csv --grid       # 四组参数稳定性扫描
python backtest.py --selftest                                   # 三场景数值自测（期望 0.996004）
python backtest.py <任意csv> --fee 0.001 --slippage 0.001 --strict  # 费滑可调；--strict 遇异常收益即报
```

> **V4 修复了两个真实缺陷**：① 换仓当日「先改仓位再算收益」导致卖出日收益与卖出成本被乘零；② 卖出成本未按成交金额真正计入。修复后成本口径为 `(fee+slippage) × |仓位变化|`，买卖双边计入，成交按当日收盘价假设。
> 回测为**基准测试策略**（MA 多头排列趋势过滤），**价格回报口径、未计分红再投资**，结果须与买入持有基准并列阅读，不代表 V4 决策信号已获历史收益验证。

## V4 升级（依据 GPT 静态评审，2026-11-06）

GPT 评审结论：系统现状为「行情采集已有、量化分析需完善、交易决策引擎薄弱、组合级风险管理缺少」，属于监测工具而非经验证的稳健决策系统。本轮只做四项 P0，逐条落地如下。

### P0-1 回测收益与交易成本计算修复（`backtest.py` 整体重写）

| 原缺陷（GPT 指出并已代码核验属实） | V4 修复 |
|---|---|
| 换仓时先 `position = new_pos` 再 `equity *= (1+ret*position)`，卖出当日收益与卖出成本被乘零 | 改为「昨日持仓结算今日收益 → 收盘成交 → 按成交金额 `(fee+slippage)×|Δpos|` 扣成本 → 次日按新仓位计收益」 |
| 买入计成本、卖出未真正计入 | 成本改为按成交金额买卖**双边**计入，输出 `cost_total_pct` 与买卖次数 |
| 成交时点假设不一致 | 统一为「当日收盘价成交」（`fill: next_close` 口径写入配置），并在 caveats 中声明 |
| 只有年化/回撤/夏普/换手 | 新增 `_perf`：CAGR / MDD / Sharpe / Sortino / Calmar / VaR95 / CVaR95 / 年化波动 / 年度胜率与逐年明细 |
| 无样本外与参数稳定性 | `run_backtest(..., oos_ratio=0.3)` 样本内外分段 + `param_grid` 四组参数扫描 |
| 无自检 | `self_test()` 三场景数值自测（期望 0.996004，实测吻合，3/3 PASS）；异常收益（|日涨跌|>11%）检测 + `--strict` |

### P0-2 风险数据缺失时的错误判断修复（`decision_engine.py`）

- **原则**：未知风险不能当作低风险，缺失数据不能用中性分数掩盖。
- `risk_metrics()` 数据不足时返回全 None 字典，原 `risk_state()` 只判 `r is None` → 末尾无条件返回「低风险 1.0」。V4 改为：`dd120` 与 `vol20_ann` 均缺失 → 返回「数据不足 / score=None / available=False」，风险维度不参与决策；判低风险时必须列出实际依据数值。
- `decide()` 原用 0.5 中性值填充缺失维度。V4 改为**只在可用维度上归一化权重**，并输出 `w`（实际权重）与 `score_scope`（参与维度），同时给出敏感性口径（35/30/35）对照分。
- 新增**数据质量闸门** `data_gate()`（P0-3 一半）：行情滞后（3 天告警 / >7 天阻断）、样本量不足、趋势缺失、风险缺失、估值不足（仅降可信度）、PE 陈旧、数据源降级、多核心维度同时缺失（阻断）。
- `decide()` 结构改为「先闸门、再否决层、最后分级」：fatal → 暂不判断；风险缺失/趋势缺失/高风险/趋势下降 → 暂停新增；>70 且高估 → 持有观察；估值缺失 → 持有观察；闸门禁止加仓 → 暂停新增。
- 评分口径修正：三维子分数为 -1..1 方向分，必须先经 `_score100` 映射到 0-100 再加权，否则「趋势下降 + 估值高估 + 低风险」会被钳制成 0 分（本轮实测发现并修复，修复前 5 只中 3 只显示 0 分）。
